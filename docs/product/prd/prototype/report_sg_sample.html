示例报告 · 业务情景为假设

在新加坡卖联网汽车，数据怎么合规地回传中国？

面向：车企 A（中国）及其新加坡子公司 B　|　依据：新加坡《个人数据保护法》及配套条例、官方指引

可以做，但在开通每日回传之前，先把三件事办好。

  • 让 B 和 A 签一份数据传输协议，写明数据去中国、A 要给到什么保护水平。现在两边之间没有这份文件，这是最大的缺口。
  • 改掉车内摄像头和定位的告知与同意。目前没有单独告知，也没有撤回入口。
  • 准备好数据泄露的应对流程。评估为需要上报后，3 个日历日内必须通知监管机构。

风险排序

1数据回传中国，没有有法律约束力的文件高
2车内摄像头图像没有取得同意、也没有单独告知高
3没有泄露响应机制，3 天上报来不及高
4云服务商 C 的责任边界没写清楚中
5没有指定数据保护负责人中
30 天内能做完的签传输协议、上线泄露应对手册、指定并公示负责人。告知同意的改造要动产品，预计 60 天。完整排期见第 8 节。

有几处我们手上的资料还没覆盖：个人数据的法定定义原文、普通联网汽车的上路认证要求、中国境内对数据入境后的处理要求。这几处在文中标了“需补充”，建议下一步一起补齐。

我们对业务的理解

A 是中国车企，B 是它在新加坡的全资子公司，负责销售和售后。联网车辆产生的数据由 B 汇集，每天批量回传给 A 在中国的数据中心，用于产品研发、OTA 升级和售后诊断。数据中心由第三方云服务商 C 托管运维。

回传的数据车辆识别码、GPS 轨迹、驾驶行为数据、驾驶员监测摄像头图像、车主账号（姓名、手机号）
已经做了的传输加密
还没有的摄像头图像的单独同意、数据保护负责人
我们还不清楚的和 C 有没有数据处理合同、有没有泄露应对流程、各类数据现在保留多久、购车协议是否把同意打包

这些情况来自一次假设的沟通，请以贵司实际为准。凡是“我们还不清楚”的，下文都标了“需补充”，补上后结论会更准。

1 · 新加坡的数据法规体系

新加坡管个人数据的核心是《个人数据保护法》（PDPA）。它把企业的义务拆成了几块，对照起来很清楚：谁负责、怎么征得同意、怎么保护、存多久、能不能出境、泄露了怎么办。 B 在新加坡经营，直接受这些规则约束；A 收到这些数据，也要通过法律文件被同样的标准约束，不能只靠“我们在中国”来豁免。（“组织”的法定定义原文需补充）

法律要求现在的情况差距风险
指定负责合规的人，并公开联系方式还没有指定未达到中
有制度和投诉渠道尚不清楚需补充—
建议由现有岗位兼任数据保护负责人，在官网和 App 公示业务联系方式；用三个月把隐私政策改成覆盖车辆数据，并建好投诉流程。责任人：B 的合规负责人。完成标准：公示页面上线、政策与流程文件归档。

2 · 数据怎么分类

能指向具体某个人的数据，要按个人数据管：车主的姓名、手机号、账号，能认出驾驶员的影像，跟车主绑定的行驶轨迹。（个人数据的法定定义原文需补充，下表是先按保守口径分的）特别要注意账号：账号标识加上密码、安全码或生物识别信息，新加坡的规定直接把它列为“可能造成重大伤害”的数据，泄露后更容易触发上报。

数据能否认出个人建议保护等级
姓名、手机号、账号能高
驾驶员监测摄像头图像能（可认出驾驶员）高
GPS 轨迹和车主关联时能中高，保留期要短
车辆识别码和车主关联时能中，随车主信息一起管
纯机械、工况参数无法关联个人时不能低（要先验证“确实无法关联”）
建议先画一张数据地图：每个字段从哪来、到哪去、做什么用、存多久。再据此分级。责任人：B 与 A 的数据治理小组，30 天。

3 · 数据回传中国，要先具备什么

把数据从新加坡发到 A 的中国数据中心，在法律上是“向新加坡境外传输个人数据”。传输之前，B 必须采取合适的步骤，确认接收方受到有法律约束力的义务约束，保护水平不低于新加坡的要求。 现在这一步是空的。

可以选的路径

路径要点适合你们吗
签合同合同要求接收方提供不低于新加坡的保护，并写明数据可以传到哪些国家适合。B 与 A 签集团内数据传输协议，写明目的地是中国
集团约束规则只能用于有关联关系的接收方，要列明适用对象、目的地国家、权利义务适合长期集团内传输，A 是 B 的母公司，符合条件
认证接收方持有指定认证，即视为受约束暂不适合：A 目前没有这类认证
个人同意要先用书面说明保护水平，不能把同意当成服务前提只作补充。官方指引建议前几条走不通时再用

两个细节值得留意。其一，如果数据放在 A 自有、自己维护的服务器上，数据仍算在企业控制之下，企业要遵守全部保护义务；交给第三方处理，才适用传输限制。 C 在这里到底是受托处理方，还是只是 A 自有设施的运维，要看合同怎么写。（需补充）其二，“认证”的范围，条例文本只列了亚太经合组织的两类体系，而官方指引还提到了全球跨境隐私规则等体系，二者不一致，需要核对条例的后续修订。（需核对）

法律要求现在的情况差距风险
传输前确认接收方受法律约束没有任何文件未达到高
合同写明目的地国家没有合同未达到高
对云服务商 C 的约束尚不清楚需补充—
建议签集团内数据传输协议，条款覆盖：保护标准、目的地中国、再转移限制、泄露通知、配合审计。同时评估 A 的实际措施是否达到新加坡的保护水平，评估记录要留存。责任人：B 的法务，30 天。完成标准：协议签署、评估记录归档。

另外，这个场景是新加坡的数据流向中国，数据到中国之后适用的中国境内规则，不在这次评估范围内，建议单独做一份。

4 · 告知与同意

收集、使用、披露个人数据，需要本人同意，或者属于法律允许的例外。 同意要有效，前提是企业先告知了用途。 企业也只能为“一个合理的人会觉得恰当”、且已告知本人的目的去用数据。 本人可以随时撤回同意，企业收到通知后要告诉他撤回的后果，并让数据中介一起停止使用。

你们最容易出问题的是车内摄像头。把驾驶员图像用于“产品研发”，和用于“保障行车安全”，是两种不同的目的，需要分别说清楚。如果把超出提供服务所必需的同意，作为买车或用车的条件，这样得来的同意是无效的。

法律要求现在的情况差距风险
摄像头图像的目的告知和同意没有单独设置未达到高
研发目的是否已在隐私政策中披露尚不清楚需补充—
不得把过度的同意作为服务条件购车协议怎么写，尚不清楚需补充—
撤回机制，并通知云服务商一起停止还没有设计未达到中
建议把同意分成两层：“提供车辆功能所必需的”，和“研发改进等非必需的”。非必需的单独勾选、可随时撤回。摄像头图像在车机首次启用时弹窗说明用途，默认只在车内本地处理，要上传的话另行征得同意。撤回后 B 通知 A 和 C 停止使用。责任人：产品和法务，60 天。完成标准：新版车机和 App 流程通过评审。

5 · 存多久、怎么删

数据用完了、也没有法律或业务上继续留的必要时，企业要停止保留，或者去掉能把数据和具体个人对应起来的信息。 官方指引说明：匿名化之后再也无法对应到个人，就视为已经停止保留。 同时，企业要用合理的安全措施，防止数据被未经授权地访问、复制、修改、处置，也要防止存储设备丢失。

法律要求现在的情况差距风险
按数据类别设定保留期，到期销毁或匿名化尚不清楚需补充—
合理的安全措施只确认了传输加密部分达到中
建议按第 2 节的分类做一张保留矩阵：GPS 轨迹和摄像头图像的保留期要明显短于账号数据；到期自动销毁或匿名化，并留存执行日志。安全措施补上云端的访问控制、密钥管理和日志审计。责任人：A 的数据治理、C 的运维，90 天。如果涉及新加坡公共道路的自动驾驶试验，另有 3 年的保留要求，见第 7 节。

6 · 出事了会怎样

监管机构可以下指令让企业整改，比如停止违规收集使用、销毁不当收集的数据，也可以对故意或疏忽违反规定的企业处以罚款。 我们取得的法条文本显示罚款上限为 100 万新元；这份文本是不是现行版本、有没有按营业额计算的更高上限，需要对照官方现行版本核实，在核实之前，不建议向管理层报具体上限。（需核对）

实际风险最集中的是数据泄露。企业一旦有理由相信发生了泄露，就要尽快评估是否属于必须上报的泄露。 涉及“重大伤害”，或者影响 500 人及以上，就必须上报。 评估为必须上报之后，最迟 3 个日历日内要通知监管机构，上报内容有明确清单。 联网汽车一次回传就是成批的数据，500 人这条线很容易越过。

法律要求现在的情况差距风险
泄露评估，必要时 3 日内上报没有流程（需确认）未达到高
云服务商发现泄露后及时通知企业尚不清楚需补充—
建议写一份泄露应对手册：发现、评估、上报、处置、复盘。明确 3 日的倒计时从“评估为必须上报”那天算起。在和 C 的合同里写明发现泄露后立即通知。每半年演练一次。责任人：B 的合规、A 的安全团队，30 天。

7 · 上路与准入

我们目前手上和这个场景相关的新加坡准入资料，只有自动驾驶车辆试验的申请指引。按假设，你们暂时不做公共道路的自动驾驶试验，所以它不直接适用；普通联网汽车在新加坡的认证和上路要求，我们的资料还没覆盖，需补充。

如果以后要在新加坡公共道路做自动驾驶试验，对数据的影响会很大：车辆要先通过安全评估和检查； 要装持续运行的数据记录装置，数据只读保存，试验期间和结束后至少 3 年要留着，随时给主管部门调取； 每个运行日结束后 1 天内，要通过指定接口把数据提交到主管部门的监测系统； 事故或事件要在 24 小时内报告。

对回传中国的启示这些数据既要留在新加坡、随时可调取，又要提交给主管部门，所以不能因为回传了中国，就只在境外保留一份。方案里要设计“新加坡本地留存一份、对外传输一份”。

8 · 怎么改，先改什么

下面的顺序按“风险高、能快速见效”排，同一个动作能解决的几个问题合并在一起。

时限要做的事谁来做做到什么算完成

90 天数据地图、分类和保留矩阵数据治理矩阵获批，有销毁日志
90 天补充云端安全措施A 安全、C 运维安全基线检查通过
