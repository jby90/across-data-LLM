# 成熟报告长什么样：调研记录与对我们报告的建议

目的：甲方没有样本、八个方面是他们规定的；我们自己也在纠结篇幅、密度和表格。这份调研看**公开的成熟报告**和**GitHub 同类项目的真实输出**，回答三个问题：报告多长合适、哪里该用表格、怎么让业务负责人愿意读。

## 先说清楚：我读到了什么、没读到什么

| 来源 | 读到的程度 | 说明 |
|---|---|---|
| White Rook《安全差距评估报告》示例（45 页 PDF） | **读了原文**（本地抽取文字） | 真实咨询公司的示例，目录、摘要、主题建议表都看到了；后半部分附录只看了目录 |
| DLA Piper《世界数据保护法：新加坡》（13 页 PDF） | **读了原文前半**（定义、主管机构等） | 看到章节结构和写法，转移章节我只通过搜索结果了解 |
| iManage 跨境传输影响评估（59 页 PDF） | **读了开头和结尾** | 看到章节骨架和篇幅，中间的目的地国法律分析没逐页读 |
| CNIL 传输影响评估实务指南（28 页 PDF） | **读了结论部分** | 看到“结论勾选项”和关于摘要的警告，其余没逐页读 |
| due-diligence-agents 在线示例报告 | **读了前 10 万字符（共约 29.5 万）** | 看到执行摘要和发现的版式，后面的章节没读 |
| GaganGanesh98/german-compliance-agent、wnallen/dpia-generator、WenzhuoXu/lawgent 的 README | **只读了说明文档** | **没有找到任何一个给出真实输出样例**，只有对输出结构的文字描述 |
| CyberSierra ISO 27001 样例 | 读了摘要的描述 | 样例本身很短，是教学性质 |
| 中国官方“数据出境风险自评估报告”模板结构 | 通过律所文章的转述 | 没有读到网信办模板原文，需要采集原文后核实 |

**没找到的：** 汽车行业专门的合规咨询报告样例；任何一家四大所的内部模板；GitHub 项目的真实输出文件。下面的结论只能说“通用的成熟做法”，不能说“汽车行业就是这样”。

## 发现一：成熟报告几乎都是“分层”的，不是一份长文

**White Rook 安全差距评估（45 页）**
- 前 3 页是执行摘要：背景（几句）→ 发现摘要（**一张小表**）→ **主题建议表**（两列：主题｜建议，7 行）→ 一小段“做得好的地方”。
- 正文按领域各 1 页左右。
- **详细建议全部放在附录**（附录 C、D 共十几页），正文只放主题级建议。
- 全文 45 页里，业务负责人真正需要读的是前 3 页。

**due-diligence-agents 在线示例报告**
- 开头是“有条件通过”的**判定徽章**，随后是约 900 字的叙述式摘要、几条要点、五个最大风险。
- 随后按“决策 → 行动 → 各领域 → 完整证据”逐层展开，**每层默认折叠**。
- 单条发现是**一段话 + 1 至 5 条原文引用**，约 100 到 250 字，**不是表格**。
- **表格只用于两处：类别汇总、行动清单。**

**lawgent（开源法律助手）的输出约定**
- 规定“先给结论”“在使用处引用”“有行动要求时结尾给步骤”“全文只有一个来源列表”。
- 篇幅分档：`brief` / `focused` / `full`，由用户选，**不是一刀切**。

## 发现二：表格该用在哪里

| 用途 | 成熟做法 |
|---|---|
| 风险排序、行动路线图、汇总统计 | **用表格**（行与行之间需要比较） |
| 单条发现 | 短段落或带标签的几行，**不用多列表格**（CyberSierra 样例：状态 + 观察约 35 字 + 建议约 22 字，全是带标签的文字） |
| 差距登记表（逐项要求、现状、差距、优先级、责任人、时限、完成标准） | **放附录**，给需要逐项核对的人（Privacy Global 的差距评估指南列出的就是这些列） |
| 主题级建议 | 两列表（主题｜建议），不是五列 |

我们现在每个方面一张五列表，等于把“附录里的登记表”塞进了正文，这是读起来像文档而不像顾问写的东西的主要原因。

## 发现三：国家法规概述的成熟写法是“按主题的短文”

DLA Piper 的《世界数据保护法》每个国家 11 到 13 页：定义、主管机构、注册、收集处理、跨境传输、安全、泄露通知、执法……**短小段落、小标题、几乎没有表格**，每章标注“最后修改日期”。
这正对应我们八个方面里“法规体系”“定义与分类”这类偏**解释**的章节：写成短文，不要表格。

## 发现四：开源项目的共同做法

- **结论优先、证据可追溯**：german-compliance-agent 每条发现是 状态（合规 / 部分 / 违反 / 未涉及）+ 严重度 + 理由 + 逐字条款；due-diligence-agents 每条发现带页码和引文，并自动检查引文真实存在。这和我们的“证据账本”方向一致。
- **风险等级由程序按矩阵算，不让模型自己写**：wnallen/dpia-generator 用 3×3 的“可能性 × 严重度”矩阵，**模型写的等级和矩阵算出的不一致，构建直接失败**。我们已经这样做了。
- **跨境传输作为一项输入事实先收集**，缺什么就列成待问问题，不猜。我们的追问机制已有。

## 发现五：跨境传输评估的公开范例有一个反面教训

iManage 的公开 TIA 有 **59 页**，大量篇幅是背景介绍（什么是 Schrems II、什么是 EDPB 建议），真正的结论要翻到很后面。CNIL 的指南还专门提醒：**只给“简单结论或执行摘要”而不附具体依据，不能算履行义务。**
→ 启示：给业务负责人的是**短的决策页**，但**依据和细节必须在附录里完整保留**，不能为了短而省掉。

它的有用部分是骨架：EDPB 六步（了解传输 → 确认传输工具 → 评估目的地法律 → 补充措施 → 程序步骤 → 定期复评），以及 CNIL 的**结论三选一**（可以传输 / 加补充措施后传输 / 不能传输）。

## 发现六：中国出境这一侧的“官方骨架”

律所文章转述的网信办《数据出境风险自评估报告》模板四部分：自评估工作简述 → 出境活动整体情况（处理者、业务和系统、拟出境数据的规模和敏感程度、安全保障能力、境外接收方）→ 逐项风险评估（重点写问题与整改）→ 风险自评估结论。申报时目录要严格按模板，至少具体到三级标题。
→ 启示：如果日后要生成**申报用**材料（需求里的第 1 类和第 2 类文件），骨架已经由官方定死，那是另一种文件；**咨询报告和申报材料不要混成一种格式**。

## 对我们报告的建议（按你关心的三点）

### 1. 篇幅：分三层，默认只展示前两层
| 层 | 内容 | 目标篇幅 | 谁读 |
|---|---|---|---|
| 第一层 决策页 | 判定徽章 + 一句话 + 3 件先做的事 + 风险排序（≤5 行表） | **1 页** | 负责人 |
| 第二层 八个方面解读 | 每个方面：结论 + 2 到 4 条发现（每条一小段，带角标） + 该方面的建议 | 每方面约半页，**共 4 到 5 页** | 业务、法务 |
| 第三层 附录 | 逐项差距登记表（五列表搬到这里）、完整路线图、参考文献 | 不限 | 要逐项核对的人 |

导出提供两档：**摘要版**（第一层，1 到 2 页）和**完整版**（三层）。这与 lawgent 的 brief / full 档位是同一思路。

### 2. 密度：每个方面写“短文 + 一两个重点”，不要写成表
- 结论 2 到 4 句；每条发现 60 到 150 字，用带标签的几行：**要求 / 你们的现状 / 差距在哪 / 建议**。
- 加粗每段最多两三处（已实现）。
- 偏解释的方面（法规体系、定义与分类）写成短文，不出差距表。

### 3. 表格：从“每方面一张五列表”降到三处
- 风险排序（决策页）。
- 整改路线图：按 **30 / 60 / 90 天分阶段**，每阶段几条（CyberSierra 的样例就是三阶段、每阶段三条要点）。
- 附录的差距登记表。

### 4. 其他
- **不引入“风险评分 62/100”这类数字。**due-diligence-agents 有，但那是它自己的模型；我们的等级来自“可能性 × 影响”的离散档位，加一个看起来精确的总分会让人误以为有标准。
- 判定徽章用四个词（可行 / 有条件可行 / 暂不建议 / 信息不足），已有。
- 每个国家的“法规概述”可以参考 DLA Piper 的主题式短章，做成可复用的国家章节，30 国共用。

## 需要和甲方确认的两个问题（不要替他们决定）
1. 摘要版（1 到 2 页）和完整版，他们想默认给客户哪一个？
2. 逐项差距登记表放附录，他们是否接受？（需求文档里提到“风险判定矩阵：业务事实｜适用条款｜合规义务｜风险等级｜判断依据”，这很可能就是他们心里的表格，**把它放附录而不是删掉**，两边都能满足。）
