# 报告改造与后续工作计划（依据 2026-10-27 甲方会议）

## 0. 会议结论与我们的判断

甲方不满意的核心：**流程跑通了，但报告是法条摘抄的罗列，没有对车企业务场景的差距分析、风险识别和工程化建议，也没有总结。** 法条应是“引用项”，不是正文。

对照当前代码（`backend/app/analysis/pipeline.py::_compile`，`prompts.py`）确认问题出在设计而不是细节：

| 现状 | 后果 |
|---|---|
| 每维度正文 = 依据条款的“义务”转述列表（`- [D3-C1] 义务（风险：…）`） | 满篇条文转述，读不出结论 |
| `key_recommendations = "核对并落实：" + 原义务文本` | 建议就是把义务再说一遍，没有工程化动作 |
| `executive_summary` 是模板句（共 N 条结论通过核验，覆盖 x/8 维度） | 没有结论、没有 Top 风险 |
| 提示词的目标是“一条原子规则，保留原文限定” | 模型被要求**不做分析**；业务事实只用于追问，不进入差距判断 |
| 风险等级只是模型给每条义务贴的 HIGH/MEDIUM/LOW | 不是“业务现状 vs 法规要求”的差距风险 |

当前流水线的**证据闸门（逐字引文、数字核验、独立支持度判断、来源隔离）是资产**，必须保留；缺的是闸门之上的“分析与咨询层”。

## 1. 业务最优实现调研

### 1.1 行业里合规评估/差距分析报告的通用结构
- 执行摘要（约 1 页）：范围、总体结论、Top 风险、需要的决策与时限。
- 方法与局限：评估依据、事实来源、未覆盖事项。
- 风险视图：按“可能性 × 影响”矩阵或红/黄/绿状态，指出重复出现的系统性问题。
- 逐项发现：每项要求 → 现状 → 符合/部分符合/不符合/信息不足 → 差距类型 → 优先级 → 整改建议。
- 路线图：每项含差距、风险分、动作、责任角色、时限、所需资源、完成标准；常见节奏为 30–60 天处理关键项、90–180 天处理中等项，关键项在无法落实时需正式的风险接受记录。
- 法律依据放在每项发现的引用/附录，不占正文。

来源：[Compliance Gap Analysis 要素与最佳实践](https://alp.consulting/what-is-compliance-gap-analysis/)、[GDPR Gap Assessment Guide](https://www.konfirmity.com/blog/gdpr-gap-assessment-guide)、[Compliance Risk Assessment 示例报告](https://www.accountablehq.com/post/compliance-risk-assessment-example-template-steps-and-sample-report)、[跨境传输影响评估（TIA）流程与风险分级](https://www.cybersecurityattorney.com/cross-border-data-transfers-sccs-bcrs-and-transfer-impact-assessments-explained/)。这些是通用资料，**不是汽车行业专用模板，也不是四大所的内部模板**；搜索没有找到公开的车企合规评估样本，这正是甲方要我们（金伯胤老师、陈博士）去找行业样本的原因。

### 1.2 汽车数据跨境场景的专业内容要点
- **中国出境**：数据出境须先做“数据识别”（是否重要数据、个人信息规模与敏感度）再选路径——安全评估申报 / 标准合同备案 / 认证 / 免于。申报材料包括申报书、风险自评估报告、法律文件；标准合同备案要附个人信息保护影响评估报告（出境版模板：处理者情况、出境业务与系统、出境个人信息、保护能力、境外接收方等）。最新的《汽车数据出境安全指引（2026 版）》给出了汽车场景的阈值与豁免。来源：[数据出境安全评估办法](https://www.cac.gov.cn/2022-07/07/c_1658811536396503.htm)、[国家数据局：汽车数据出境相关文件](https://www.nda.gov.cn/sjj/zwgk/zcfb/0203/20260203171849356062918_pc.html)、[锦天城：申报与备案指南（第二版）解析](https://www.allbrightlaw.com/CN/10475/276b4f60f115f63d.aspx)。**具体阈值与条文必须以原文为准，实现时只能经本平台的证据闸门引用，不能硬编码进提示词或代码。**
- **入境欧盟/车联网隐私**：[EDPB Guidelines 01/2020](https://collab.dpa.gr/wp-content/uploads/2023/07/EDPB_Guidelines_01-2020_connected_vehicles_and_mobility_related_applications_v2_en-1.pdf) 的工程化建议（车内处理优先、出境前匿名化/假名化、位置与生物特征最小化、按车密钥管理、日志留存）是“工程化建议”的典型素材。
- **TIA 通用做法**：描述传输 → 目的地法律环境 → 供应商控制措施 → 补充措施（技术/合同/组织）→ 剩余风险与复评触发条件。
- 新加坡、埃及、突尼斯、摩洛哥、黎巴嫩的专项做法（如新加坡的转移限制义务与相关指南）**需要从我们已入库的官方原文和监管机构指南中取证，不能凭记忆写入**；可作为调研清单，不是结论。

### 1.3 “最优实现”的判断
好的报告 = **证据账本（已核验的法条/条款）+ 业务事实 + 差距判断 + 建议**，三层分工：
1. 证据层：保持现有闸门，输出可定位的“证据单元”（条款、版本、逐字引文、核验状态）。
2. 分析层（新增）：把“业务事实”与“证据单元”逐项对照，输出符合性判断、差距、风险分（可能性×影响，规则透明）、判断理由。
3. 咨询层（新增）：汇总成执行摘要、Top 风险、整改路线图、需要用户补充的信息；引用只以角标指向证据层。

## 2. 报告改造设计

### 2.0 核心转变：从“找法条并列出”到“咨询师基于依据写报告”
当前工作流的产物是**证据清单**，用户读到的就是清单。改造后，找法条只是中间环节：
- 检索、选证、核验产出“证据账本”，**默认不直接展示**，只以角标和附录出现；
- 新增“咨询顾问”环节，作为报告的**主要作者**：读取证据账本和用户业务事实，像咨询师一样先给结论，再讲清楚“对你的业务意味着什么、差在哪、先做什么”，用连贯的行文而不是条文罗列；
- 行文由模型写，但每个法律性陈述必须挂证据角标，建议必须落到具体差距，由程序校验（见 2.2），所以“像咨询师”不以牺牲“不编造”为代价；
- 用户看到的第一屏是结论和行动建议，想核对时点角标看原文。
- **法条只以参考文献方式呈现**：正文只出现编号角标如 [1][2]，不摘抄、不转述整段条文；文末“参考文献”按编号列出法规名称、条款位置、版本、官方来源链接、获取日期，必要时附一句关键原文摘录；同一条款只编一个号，多处引用复用。原文全文、中文对照和核验状态在角标弹窗/附录中查看（沿用现有引用抽屉），Word/PDF 导出同样是“正文角标 + 文末参考文献”。
- 实现含义：①选证阶段不变，但写作阶段禁止大段引用原文（程序限制正文中引文占比，超限退回）；②引用编号由程序统一分配，模型只输出证据 ID，避免编造或错号；③每个参考文献必须被正文至少引用一次，正文每个角标必须能对应到参考文献。

### 2.1 新报告结构（用户端与导出一致）
1. **执行摘要**（≤1 页）：总体结论（可否出境/需满足哪些前置条件）、风险概览（热力图/计数）、Top 5 风险、最紧急的 3 个动作、置信度与未覆盖事项。
2. **业务场景与假设**：用户事实表（来自对话，标明哪些是用户确认、哪些缺失）。
3. **八维度分析**，每维度固定四块：
   - 结论（2–4 句，直接回答该维度对该场景意味着什么）；
   - 差距分析表：要求｜业务现状｜符合性（符合/部分/不符合/信息不足）｜风险（等级+理由）｜证据角标；
   - 建议（工程化：动作、责任角色、建议时限、验收标准）；
   - 待补充事实（驱动追问）。
4. **整改路线图**：跨维度合并，按优先级排序（30/90/180 天），去重（一个动作解决多个差距）。
5. **参考文献**：法条仅在此以编号列表呈现（法规名称、条款位置、版本、官方来源、获取日期、核验与人工复核状态；原文和译文在弹窗或附录中查看），正文用角标引用。

### 2.2 流水线改造（不削弱现有闸门）
在 `node_dimension_analyst`（证据→核验）之后、`node_report_compiler` 之前新增两个节点，沿用 Agent Studio 的版本化工作流配置（提示词、模型、拓扑均为可激活的版本）：

- **node_gap_assessor（差距评估）**
  - 输入：该维度已通过核验的证据单元 + 用户业务事实 + KG 中的关联义务/罚则。
  - 输出（结构化 JSON）：`assessments[]`，每项含 `requirement`（基于证据的一句话要求）、`business_state`（引用的用户事实键，或“未提供”）、`status`、`gap`、`likelihood`、`impact`、`rationale`、`evidence_refs[]`（必须是本维度已核验的 finding_id）。
  - 事实不足时输出 `needs_user_fact`（复用现有追问机制），不得猜测。
- **node_synthesizer（总结与建议）**
  - 输入：全部 `assessments`。
  - 输出：每维度结论、建议动作（`action`、`owner_role`、`timeframe`、`done_criteria`、`addresses[]` 指向 assessment）、整份报告执行摘要、Top 风险、路线图。

**程序校验（沿用“模型不可自评”原则）**：
- 所有 `evidence_refs`/`addresses` 必须指向存在且已核验的证据；断链即退回。
- 断言分类：`LEGAL_FACT`（必须带证据角标，且文字不得超出证据）、`APPLICATION`（业务事实×法规要求的推论，必须同时引用事实键与证据）、`RECOMMENDATION`（必须关联到某个差距；标注为“建议，非法律意见”）。无引用的 `LEGAL_FACT` 一律拒绝。
- 数字、日期、金额只允许来自证据或用户事实（沿用 numeric integrity 检查）。
- 风险分用固定、可见的规则（可能性×影响→等级）计算，模型只提供两个因子与理由，程序算等级；执行摘要的计数必须与明细表一致（跨表一致性检查，计划书已有此要求）。
- 证据不足的维度明确写“信息不足/待核查”，不能为了好看而写结论。人工复核状态继续逐条标注。

### 2.3 数据模型与接口
- `ReportVersion` 增加结构化字段（JSONB）：`assessments`、`recommendations`、`roadmap`、`summary_blocks`；`content_markdown` 由结构化数据渲染，保证编辑、版本、diff、导出仍可用。迁移只增量（0024）。
- 渲染层 `report_exporter.py`/`pdf_renderer.py`：新增执行摘要、差距表、路线图的 Word/PDF 版式；法条放脚注/附录。
- 用户端 `ChatAnalysis.vue` 报告卡片：摘要置顶；差距表；角标点开抽屉（沿用）。
- 工作流配置：新增节点的提示词、模型、温度进入版本化配置，可在 Agent Studio 激活和回滚；任务绑定启动时版本。

### 2.4 评测
- 新增**报告质量评分表（rubric）**：结论明确性、差距针对业务事实、风险理由、建议可执行性（动作/责任/时限/验收）、法条克制度（引用占比）、可读性、无编造。由领域专家人工打分，模型评分只作辅助；沿用冻结题集 + 新增未参与调试的场景。
- 事实一致性/引用正确性沿用现有指标；新增“建议可追溯率”（建议→差距→证据链完整率）。
- 保留现有 32 题基线，改造前后对照，不刷掉否定结果。

### 2.5 风险与边界
- 咨询层是**模型推论**，必须明确标注“基于已核验法条与用户提供事实的分析，非法律意见”；人工复核按甲方安排由第三方完成。
- 不得把某国义务套到别国；国家差异走数据/配置层（`AGENTS.md`）。
- 不引入新框架；用现有编排与 MCP 工具实现。

## 3. 其他会议待办的技术方案

### 3.1 法规信源筛选（白皮书/咨询报告误收）
- 现状：`assess_document_relevance` 只按“表格关键词”判 irrelevant，其余默认 relevant。
- 方案：增加**文书类型判定**（立法文本 / 监管指南 / 标准 / 白皮书·研究报告·新闻 / 表格），特征包括：条款结构（编号链、效力用语）、发布主体、官方域名、颁布/生效元数据；分层结果为 relevant / related / out_of_scope（沿用已有分层）并写入原因；低置信度进“待核对”，由管理员确认，不静默丢弃。
- 站点层：来源条款批准时登记“可收录的文书类型”，作为配置而非代码特判；增加存量文档的**一次性重分类报告**（只标记，不删除，保留历史）。
- 验收：对五国 81 份文档逐份人工抽检，输出误收/漏收清单。

### 3.2 非英语 OCR（埃及优先）
- 现状：Tesseract（eng/ara/fra），每份最多 40 页，超出静默丢弃；埃及阿语扫描件质量不足，6 题证据缺口。
- 方案：
  1. 先建**OCR 评测集**：从埃及、突尼斯、摩洛哥扫描件选页，人工校对出标准文本；指标：字符/词错误率、条款编号保留率、阿拉伯语数字与日期正确率、成本/页、耗时。
  2. 对比候选：现有 Tesseract 基线、付费云 OCR/文档智能服务、多模态大模型识别。具体产品由陈博士测试选定；调研时需核实阿拉伯语支持、价格、数据出境与保密条款（法规原文为公开资料，但仍要经 `LLM_DATA_EGRESS` 评审）。
  3. 以**可插拔适配器**接入 `ingestion/ocr.py`（按语言/版面特征选引擎，配置驱动）；输出统一带置信度，低置信度页进人工核对；取消静默截断，超页数要拆批并记录事件。
  4. 埃及：重新获取个人数据保护法及其实施条例的官方 PDF（核实官方发布与获取状态），经新 OCR→条款切分→翻译→人工核对，作为下一阶段试点验证。OCR/翻译产物保持“待核对”和“机器翻译”标注，不当作官方文本入库。
- 验收：埃及两部文件条款完整率与编号连续性、抽检 20 条错误率、6 个证据缺口题的复测。

### 3.3 行业最佳实践样本与格式约束
- 由金伯胤老师、陈博士收集样本；我们提供**检索清单与评审表**（见 §2.4 rubric），并先产出“参考提纲 + 两份人工标杆样稿（新加坡车联网场景）”供甲方确认，再据此约束提示词与版式。
- 不使用来源不明的样本作为法律依据；样本只用于结构、深度和措辞风格的校准。注意版权，样本仅内部参考，不进入产品内容库。
